# Lessons from `proto/cpp` (context for the new port, not binding design)

Every path below (`design/*.md`, `design/_memory/*`, `CMakeLists.txt`, `cmake/*.cmake`,
`cpp/...`, `pyproject.toml`, `CMakePresets.json`) refers to branch `proto/cpp` of FELIGN/pantr,
not to this repository; issue numbers refer to FELIGN/pantr too. "Working notes" are the first
attempt's private notes, not published; their content is restated here. A claim is only as
strong as the source it cites. "Dual" = existed only because two backends had to agree.

Several questions in section 3 are now settled by the port's own brief: dense linear algebra is
Eigen (3.1), the root-finding seam has BeRF-FR as its optional provider (3.6), `pantr.mpi` gets a
C++ layer (3.9), and the Python floor is 3.12 (3.11).

## 2. Build and toolchain traps (flags verified by opening the file)

- **nanobind `-Os` after `-O3`.** `nanobind_add_module()` appends `-Os`, last flag wins, kernels compile for size (effect: about a factor of three, silent). Fix: `nanobind_add_module(_pantr_cpp NB_STATIC NOMINSIZE NOSTRIP ...)` (`cpp/bindings/CMakeLists.txt:133`) and `install.strip = false` under `[tool.scikit-build]` (`pyproject.toml:154`), because scikit-build-core strips again at install. A standalone C++ benchmark never sees this; keep both benchmarks. Check effective flags before any timing. (`design/build_findings.md`)
- **Split mode (nanobind 3, pre-release when tested):** `nanobind_add_module(_pantr_cpp NOMINSIZE NOSTRIP NB_SUPPRESS_WARNINGS BACKEND_MODULE nanobind_backend ...)` (`CMakeLists.txt:119`). `NB_SUPPRESS_WARNINGS` is mandatory or `-Wshadow` in `nb_attr.h` meets `-Werror`. `nanobind-backend` becomes a runtime dependency. Behavior matched `NB_STATIC`; choice is packaging only. At HEAD split is an option (`PANTR_NANOBIND_SPLIT`, default OFF), `pyproject.toml` still builds `NB_STATIC`, `STABLE_ABI` deliberately not used. (the first attempt's working notes)
- **nanobind headers and `-Werror`:** for `NB_STATIC`, retag `nanobind-static` includes as `INTERFACE_SYSTEM_INCLUDE_DIRECTORIES` by hand (the `foreach` at `cpp/bindings/CMakeLists.txt:159`); GCC drops an `-isystem` already given as `-I`.
- **Multi-ISA:** only composition was verified (two frontends at different `-march` against one backend import together). No ISA ladder was built; build files carry no `-march` on purpose. Probe module must be baseline, fail closed (OS vector state, not just CPUID), explicit override must not fall through, ladder follows the target not the host. `-march=native` was slower than `x86-64-v3` on one kernel. (`design/simd.md`, the working notes)
- **Raising the ISA under GCC breaks Eigen:** AVX-512 TRSM kernels trip `-Wmaybe-uninitialized`; fix is `EIGEN_USE_AVX512_TRSM_KERNELS=0` on `pantr_core` for GNU. Do not use `-Wno-maybe-uninitialized`. It changes which code does triangular solves. (`CMakeLists.txt`, comment above `target_compile_definitions`)
- **Editable-install finder shadowing.** `pip install -e .` under scikit-build-core puts `ScikitBuildRedirectingFinder` at `sys.meta_path[0]`; it outranks `sys.path` and `pytest.ini pythonpath`, so a worktree imports the main checkout. Worktree-only modules are unimportable. Fixes: `pip uninstall pantr`; or per process, `PYTHONPATH="$(pwd)/src:a directory holding that `sitecustomize.py`"` with a `sitecustomize.py` doing `sys.meta_path[:] = [f for f in sys.meta_path if type(f).__name__ != "ScikitBuildRedirectingFinder"]`. Use a per-worktree `.venv --system-site-packages`; never `pip install -e` under `conda run` in the shared env. Check: assert `pantr.__file__` is under the tree; delete the `.so` and confirm parity tests skip. The project `CLAUDE.md` still says `pythonpath = src` is enough, which these notes contradict. (the first attempt's working notes, the working notes)
- **Stale `.so` after rebase/merge** looks like a regression in someone else's ticket. `cmake --build --preset gcc` does not build the extension. Recipe: `cmake -S . -B build/ext -G Ninja -DCMAKE_BUILD_TYPE=Release -DPANTR_BUILD_PYTHON=ON`, `cmake --build build/ext`, `cp build/ext/cpp/bindings/_pantr_cpp.cpython-*.so src/pantr/`, then check `hasattr` of a new type. (the first attempt's working notes; recipe quoted, not rerun)
- **Dependencies:** FetchContent pinned by full SHA, `SYSTEM`, `EXCLUDE_FROM_ALL`; `FIND_PACKAGE_ARGS` alone silently switched Eigen to a system copy of another major version, so `PANTR_USE_SYSTEM_DEPS` is OFF by default. CMake 4 rejects deps with `cmake_minimum_required < 3.5`: `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`. Offline: `-DFETCHCONTENT_SOURCE_DIR_EIGEN=...`, `-DFETCHCONTENT_FULLY_DISCONNECTED=ON`; a GitLab 403 once broke a fresh `pip install -e .`, so keep `build-dir = "build/skbuild/{wheel_tag}"` (`pyproject.toml:158`). (`cmake/PantrDependencies.cmake`, `design/build_findings.md`)
- **Probe cache:** switching compilers inside a build dir gives stale probe answers; one build dir per compiler (presets do this). GCC `-Wconversion` does not imply `-Wsign-conversion` (Clang does), and `-Wdouble-promotion` fired on Clang only; run every compiler leg. (`cmake/PantrCompileOptions.cmake`, the working notes)
- **Race detection:** a bare memo passed every unsanitized run yet raced under TSan; `gcc-tsan` is the only gate. ASan/UBSan preset needs `-fno-sanitize-recover=undefined` or UBSan reports and exits 0. (`CMakePresets.json`)
- **Install/export:** `PANTR_INSTALL` OFF in the wheel because the exported target has a hard `find_dependency(Eigen3)` and the wheel does not carry Eigen; C++ consumers use a CMake install. `find_dependency(Threads)` is needed (`std::mutex` in headers). Package version uses `SameMinorVersion`. `pantr::cxx_flags` (warnings, `-Werror`) is not exported; the contraction flag is. (`pyproject.toml:132-139`, `CMakeLists.txt`)
- **CPU cap and timing:** work capped at 20 CPUs via `taskset -cp 0-19 $$` plus thread variables; threaded OpenBLAS destroys small-matrix timings, so pin `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1` before timing BLAS/LAPACK; never compare single-thread C++ with threaded LAPACK here. Parallel thresholds must be derived, not measured on the server. (the first attempt's working notes)

## 3. Open questions the first attempt never closed

1. **Dense factorization: LAPACK vs Eigen (FELIGN/pantr#500).** Operations gated: periodic conversion (`qr`), `multiply` (`lstsq`), THB prolongation (`lstsq`/`gelsd`) and restriction (`pinv`), `locate`'s SVD health check, interpolation, graph partition (`eigh`: eigenvector signs). Options: Eigen (already shipped for `PartialPivLU`; `BDCSVD`; `SimplicialLDLT` chosen for banded fitting), LAPACK/BLAS (OpenBLAS vs Accelerate differ in last bits), hand-rolled banded Cholesky. With no Python backend the cross-library parity hazard goes away only if the tests do not assert discrete outcomes (rank, admissibility); that is untested. Known Eigen facts: tridiagonal eigen-solver deflation is not scale invariant and reports success; `info()` must be propagated; rank agreement with `gesdd` is asserted, not proved. Eigen forces an MPL-2.0 licence question against `pyproject.toml`'s `license = "MIT"`. (FELIGN/pantr#500, `design/large_data_fitting.md`, `design/bezier_interpolation_port.md`, `design/_memory/decisions-pointer.md`)
2. **Wheel strategy:** `NB_STATIC` vs split mode vs stable ABI; `manylinux_2_28` compiler vs the toolchain gate never checked. (`design/toolchain_requirements.md`)
3. **Ship an ISA ladder at all?** and compile-time/code-size cost of instantiating block widths times ISAs. (`design/simd.md`)
4. **Threading model in C++** (absent on purpose; replaces `prange`; serial-twin thresholds; callback single-thread rule). (the working notes)
5. **Fitting scope:** smoothing penalty in scope?; node layout (tensor vs scattered) as a type; residual in place vs alongside; THB: quasi-interpolation vs L2 per level, marking strategy. (`design/large_data_fitting.md`, `design/adaptive_thb_approximation.md`)
6. **Root-finding seam** (`root_solver_fn`, `RootResult`, pantr-owned tier ladder translated by an exhaustive `switch` in the adapter): designed, not built. Open: tier on options vs compile-time, max-tier vs capability query, whether curve-curve intersection belongs in pantr. The notes do not name the provider. (`design/root_finding_dimension.md`)
7. **Grid polymorphism:** no runtime grid type; are user-defined grids needed once Python cannot subclass them? (`design/grid_hierarchy_port.md`)
8. **Validation in a thin binding:** `PANTR_PRECONDITION` vanishes in release and the old design relied on bindings to refuse violations; who validates for C++ callers and Python users? (`cpp/include/pantr/core/precondition.hpp`)
9. **`pantr.mpi` in C++:** the design notes contain no C++ design for it beyond a `partition_fn` seam mention; a rule that kernels take no MPI type is recorded only in the first attempt's working notes (not found in `scripts/ci_local.sh`). Unverified.
10. **AD:** is `Dual<T, N>` wanted (CAD-parameter derivatives)? (`design/automatic_differentiation.md`)
11. **Python floor:** the first attempt's working notes say 3.12; `pyproject.toml` says `>=3.11`.

## 4. What made it expensive (only where a note says so)

- Parity machinery: bounds had to be derived per kernel; predicted bounds were refuted and a bound silently degenerated to zero; the harness generalized in vocabulary but not in meaning and had to be revised after first use; the oracle was not always Numba, so evidence differed per module. (`design/build_findings.md`, `design/backend_parity.md`)
- Design written without compiling; some notes amended after the compiler contradicted them; later notes carry per-claim re-verification because line locators drifted. (`design/_memory/decisions-pointer.md`, `design/bspline_ownership_lifetime.md`)
- Mid-port reversals: type ownership flipped (the amendment says it enlarged the port), Numba retirement decided after the parity rules existed; Eigen moved from test-only to shipped, retiring a rationale. (`design/cross_backend_types.md`, `design/backend_parity.md`, `design/build_findings.md`)
- Reduced CI on `proto/cpp`: only C++ jobs and parity run; lint, types, Python suite, docs by hand; the local gate script does not run the linters; merges went in with red gates; `Closes #N` creates no link, so wave planning re-dispatched built work; stacked PRs get no CI; rebase-merge conflicts per commit. (the working notes)
- Silent environment faults: wrong-package green runs, stale `.so`, shared build dirs invalidating a running check. (the working notes, the working notes)
- Agent coordination: collisions in shared worktrees (`git stash`, checkouts), `pkill` by program name, scratch root deleted, session limits killing several agents, reviewers briefed from a stale report. (the working notes)
- Many-core timing noise produced a quoted speedup that was thread noise. (the working notes, `design/bezier_interpolation_port.md`)
